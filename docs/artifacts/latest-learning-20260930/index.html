六个可以带走的方法

证据读法：原文核对＝来源明确描述过；方法建议＝本次阅读后的推断；算术示例＝人为构造并验算；本地观察＝脚本实际运行。下面六项均为“原文核对 + 方法建议”，不代表 Clade 已取得成效；第一项另含算术示例。

1. 稳定性需要单独测量

IBM Research 的一致性文章（09-15）提示：固定任务集及重复次数 k，同时报告平均成功率、至少一次成功的任务比例和全部 k 次成功的任务比例。下面是算术示例，没有调用模型。

1 表示成功，0 表示失败。每组相同 4 个任务，每任务 3 次，共 12 次；手机可横向滚动查看全部指标。

2. 核对事实，也核对它归属于哪个来源

来源核验文章（09-29）把回答拆成主张，先匹配来源，再判定是否支持、引用是否正确，最后修复或回退。实际可借鉴的是保存来源标识，避免从多篇材料拼出一句话后挂错引用。

底层论文首发于 06-16、08-27 修订，09-29 是解读日期。原实验中的“处理完成”包含回退；不能全部计为完成了有内容的回答。医学轨迹结果未在本项目复现。

3. 新模型上线时，先核对接口行为

Sonnet 5.5 迁移文档列出 thinking、历史消息和工具选择的变化。例如严格参数校验不保证一定调用工具；读取响应应按内容块类型处理。这类变化可能先影响正确性，再影响速度。

09-28 发布；未调用 API。09-29 的 GPT-6.1 Sol也应按模型与推理档位共同评估；官方成绩没有证明当前任务会得到同样收益。

4. 接收事件、执行任务、完成任务是三个状态

OpenAI 的 MCP Events 文档描述 webhook 接收与异步执行：2xx 只确认接收；重试需要稳定的事件标识和幂等写入；恢复还取决于重放能力。集成仅覆盖草案的一部分，不能把文档中的所有协议能力都当成现有功能。

截至 09-30 文档已读，初次发布日期未确定；未接入服务。Google 09-15 的实时语音更新让对话在工具执行时继续，也需要分别维护对话和任务状态。

5. 性能数字必须带上测量条件

Tokenizers v1 候选版（09-21）通过复用内存、缓存及向量化优化处理；比较时应检查 token ID 一致，并区分重复输入与新文档。Transformers 的 GGUF 实验支持（09-22）则提醒：能加载格式与能用当前设备的加速内核是两回事；首批打包内核面向 MPS。

没有做本机性能试验。比较吞吐时要统一是否包含提示词处理、批次、输入长度和硬件，不能把文中的不同计时区间直接相除。

6. 失败证据应该能被下一步直接使用

Vitest 5 的 09-28 更新说明介绍把浏览器交互、断言与页面快照留在 Trace View，并检测未等待的异步断言。Cloudflare 09-30 的故障检测 Beta把重复异常与日志、堆栈、追踪、版本信息交给后续诊断。可借鉴的是让失败自带上下文，而非只传一个红色状态。

已读发布说明；没有安装工具或连接生产账户。聚类算法、告警重试和误报率仍未知。

两个值得了解的新方向

证据等级：原文核对；下述适用判断属于方法建议，未做模型实验。

表格模型：把已知行作为预测上下文

NVIDIA Kumo-Tabular（09-29）使用带标签的上下文行预测查询行，查询只关注上下文，从而可复用上下文的缓存。它延续了表格上下文学习路线；新意在具体结构和效率设计。模型与推理代码已公开，完整训练配方和数据生成器仍计划发布。

数值、类别之外的字段需要预处理；选样、分布变化和数据泄漏仍须在真实数据上检查。没有下载权重或进行 GPU 推理。

语音合成：听得清、等得短、像本人要分别评估

Open TTS Leaderboard（09-30）分开检查转写错误率、生成吞吐、首段音频等待时间和声音相似度。错误率低不等于自然，声音嵌入相似也不等于听众偏好。

当前范围为指定英语样本与硬件；完整评测脚本尚待公开。没有做音频生成或听评。可以先学其指标分工，暂不把名次推广到中文语音。

已实测：浏览器的 8 项行为符合预期

证据等级：本地观察；以下结论仅覆盖明确列出的测试场景。

本机 Linux Chrome 154.0.8037.92，两个本地 HTTP 服务；脚本把网络测试限制为两个并发浏览器上下文。最终运行耗时 0.808 秒，8/8 项断言通过。证据是 逐项结果与服务端命中记录，复现入口为 browser_probe.py。

  • 连接限制：对照组同源、跨源和重定向均成功；强制模式允许同源请求，拦下跨源请求和重定向，对应目标端命中为零；仅报告模式仍允许请求。
  • iframe 内容高度：父页设置自适应尺寸，子页明确同意后，高度从默认 150px 变成 600px；内容变化后调用 requestResize() 更新到 900px；缺少子页同意时仍为 150px。

文档依据：连接允许列表说明（09-23，能力从 Chrome 152 起）与自适应 iframe 指南（09-16，Chrome 154 稳定版 09-22）。

范围仅限一个 Chrome 构建、回环 HTTP 和这些固定场景；未测 Safari、Firefox、WebRTC、Worker、报告上报、恶意代码隔离或线上嵌入。不把这个实验称作完整安全审计。

循环从发现，走到机制、边界和验证

先跨发布方扫描近期 AI 与工程更新，再追读迁移文档和方法章节；接着追查稳定性、引用归属与硬件条件；刷新 Hugging Face、Cloudflare 的最新目录，补入表格、语音与开发工具；最后核对所选来源状态并完成浏览器实验。最后一次扩展仍有新内容，所以没有记录“连续无新知”这种并未发生的结果。

批处理前检查了 CPU、内存和其他用户负载。实验时可用 CPU 32、负载约 5.92、可用内存约 63.9 GiB；RTX 3090 空闲显存约 18.4 GiB。限制本机库线程为 1，没有适用的 GPU 工作；未影响其他用户进程。渲染验证使用四个有界并行视口。

下一次有真实任务时，优先验证这三件事

  1. 固定任务集，重复运行并同时报告平均、至少一次和全部成功；保存每次失败轨迹。
  2. 用混合来源的回答，检查每条主张的引用归属，把修复回答与回退分开计数。
  3. 遇到浏览器嵌入或外部事件需求时，复用这次边界实验，再补目标浏览器、网络和重放场景。

这些是学习后的候选实验；负责实施与排期的是 Clade 维护者，当前没有排期。实际收益尚未验证，运行策略没有因此改变。
