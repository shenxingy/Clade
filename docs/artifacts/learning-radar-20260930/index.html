四项新材料建议先做什么证据与边界

这些术语描述的是 agent 如何完成任务

Harness 是模型外的执行层，负责工具、上下文、委派与验证。消融 是固定其他条件、只改变一个组件的对照实验。缓存成本 包括上下文首次写入、重复读取，以及切换模型后的重建。会话级评估 检查从用户目标到最终交付的完整过程。

Clade 已有委派规则，下一步要知道它在哪些任务上有效

仓库已经讨论生成与检查分离、失败回归和执行证据；当前规则也明确限定子代理职责。因此新的学习价值是测出适用边界。论文提供了拆分组件的方法；是否能提高 Clade 的可验证交付质量，需要本地任务证据。

优先 1 · 2026-09-26 · 研究论文

专门化委派值得验证，压缩收益不能默认成立

Beyond the Model / NanoHarness 在仓库级软件生成基准 ProgramBench 的组件实验中发现，结构化工具和面向具体任务的子代理更稳定；通用子代理与上下文压缩单独加入时可能降分。这是论文结果，尚未在本项目复现。

可借鉴：用同一组终端任务比较“主代理独立执行”和“现有受限委派”，再单独研究压缩。边界：组件结论主要来自 ProgramBench、Qwen 与 DeepSeek，不能直接推广到所有模型；论文的完整组合仍有收益，不能据此认定压缩永远有害。

优先 2 · 2026-09-24 首发，09-26 修订 · 研究论文

模型切换是否省钱，要算上缓存重建

Harness Tokenomics 把路由决策放在会话开始、旁路任务和子代理启动等边界，并推导中途换模型何时能够回本。可借鉴的是成本核算方法。

可借鉴：在终端实际运行路径中，把切换边界、缓存重建与成功交付总费用对应起来。现有 agent_output.py 已解析缓存字段；routing_break_even.py 使用上游总费用作观察性统计，未建立缓存重建的对照。后两者属于当前休眠的 orchestrator，不能当作终端已实现。边界：论文依赖仿真、公开会话及特定日期的单厂商价格；其节省比例不是 Clade 的实测值。

优先 3 · 2026-09-21 / 09-25 · 产品团队文章

窄范围判断可以返回类型和概率，再由代码决定流程

LangSmith 接入 Jev，让判断直接返回布尔概率、选项或等级；后续 LangGraph 示例 展示如何把判断接入明确的流程。

可借鉴：先在离线数据上评估“是否发生用户纠正”“是否需要升级复核”等窄问题，给不确定结果保留复核路径。边界：速度和准确率来自作者选定场景，不能证明适合本项目；不把这种判定直接用作自动批准。接入依赖外部 API，价格、许可和数据条款尚未核验。

优先 4 · 2026 年 9 月更新，覆盖 08-06 至 09-18 · 产品公告

完整会话应该能被标注、复核和评价

Arize AX 的会话级工作流 支持对整个会话标注、加入复核队列并预览评估结果。公告只标到月份，不能把抓取日期当作发布日期。

可借鉴：把“用户纠正 → agent 修复 → 独立验证 → 最终交付”放到一个可复核对象中，检查中途成功是否真的兑现为交付。已有基础：session-scorecard.sh 已记录会话纠正、提交和回退；loop_verify.sh 已记录修复变化。此项是补充完整会话的人工标注与复核路径，不是重新建设基础追踪，也不意味着要采购 Arize。

下一步先写出终端委派对照方案

建议负责人：Clade 维护者。建议时间：下一次评估迭代；2026-09-30 提议，未排期。
