本地证据学到什么对照方案来源与复跑

红绿校准测试的是判定能力

红组：在固定版本中，仅把待修文件换回父提交实现，保持测试不变。绿组：同一固定版本及其测试。红组只允许出现指定的回归失败，绿组必须全过。Agent 对照则要让模型实际完成任务；本次这类试验运行数为 0。

论文的价值在于任务匹配，不能直接变成全局开关

NanoHarness 原文 §3–5、§7：专门化角色负责行为分析、差分测试和提交检查；组件实验使用 200 个 ProgramBench 任务及两种模型，设置为非思考模式、温度 0。单独压缩的负效应不能否定完整组合。正文未明确给出重复次数或置信区间，本次也未定位到可确认属于作者的代码快照。

ProgramBench 要求根据二进制与文档重建行为。其官方评分说明把完整解决率与平均测试通过率分开；因此本文不把 NanoHarness 的 score 转写为成功交付率，也不与实时榜单直接比较。

对 Clade 的推断：子任务应绑定一个待消除的不确定性，例如定位失败输入或检查行为差异，并返回可独立核验的证据。现有受限委派规则已接近这个方向；是否带来净收益需要独立实测。

关于压缩的推断：下一轮应检查压缩后是否保留验收条件、已证伪假设、相关文件和验证结果，再观察失败变化。这里提出的是对照项目，没有改动运行时压缩行为。

探索是否有价值，要看它回答了什么问题

针对本地任务，我会把每轮探索写成“待确认行为 → 最小观察 → 结论 → 是否继续”。以机器通知误报为例，先确认通知是否写入指纹日志，再检查真人重复输入是否仍能触发信号；同一个问题已有直接证据后，不再扩大无关仓库扫描。

可复用的委派任务卡：问题、允许读取的路径、可修改范围、资源上限、返回格式。返回内容必须包含结论、文件或命令证据、反例与未知项；主代理负责最终核验。这个例子是本次学习后的操作建议，符合现有规则，不是新增全局策略。

下一步的对照必须只改变委派这一项

负责人：Clade 维护者。提议日期：2026-09-30；正式模型试验未排期。本次已完成阅读、校准和以下试验设计。

  1. 固定输入。在无修复提交历史的独立任务快照中运行；两组拿到同样的需求、工具和可信指令。最终评判测试由外部验证器持有，模型不能修改。以上两项只能作为局部修复的预实验，扩展结论前须补充新任务。
  2. 隔离变量。A 组主代理独立完成；B 组同一个主模型可启动一个同模型只读专门化子代理。固定版本、effort、总预算、上下文上限和超时；B 组预算包含子代理开销。不同时改变压缩、工具或技能。此试验是建议，未覆盖或改变本会话的委派规则。
  3. 区分两个问题。先检验委派本身；之后再单独比较便宜子模型策略。若一开始同时换模型，只能评价整套策略，无法归因于委派。
  4. 记录全部尝试。预先锁定试验次数，交替执行顺序。记录实际模型、工具/技能版本、缓存状态、重试、墙钟时间、父子用量、最终验证及错误放行。未知费用记为未知；失败尝试的费用也计入总费用。
  5. 接受反证。两组成功率相同而委派更慢或更贵，就保留独立执行。按任务分别展示差异与重复运行的离散程度；这两项校准不能支撑总体显著性结论，也不能作为盲测集反复调优。

完成定义：另一位维护者能重建相同任务与对照条件，复算验证成功率和“全部尝试总费用 / 验证成功交付数”；成功数为零时费用指标记为未定义。生产策略变更需要这些实际结果支持。
