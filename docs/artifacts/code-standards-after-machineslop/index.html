Code standards after machineslop

An agent writing code no human reads is not a new engineering problem. It is the old one — unverifiable work — arriving through a new door. The popular diagnosis is mostly anecdote. The measured answer points somewhere else entirely, and it points at us.

Alex Shen · aries 29-agent sweep, 6 adversarial attacks Sources checked against primary documents

The trigger was Armin Ronacher's weekend run: 35 hours unattended, 75k lines, 79 commits, ~$1,200, and by his own account "absolutely nothing of value." The conclusion everyone drew is that models are learning to write for machines. Six adversarial passes later, that framing did not survive — and neither did the comfortable rebuttal that our gates would have caught it.

  • 01

    Cleanliness bought no correctness — in a controlled trial

    Minimal pairs differing only in static-analysis violations and cognitive complexity, 6 pairs, 33 tasks, 660 trials, graded by hidden tests: pass rate 0.913 clean vs 0.921 messy. The thing we were about to gate is the thing measured not to matter — for correctness.

  • 02

    But naming is load-bearing for the machine

    Stripping identifiers costs 11–28.6 points of accuracy. Names act as retrieval cues into memorised patterns, so a model may degrade faster than a human when they go. Machine-readable is not a weaker constraint than human-readable along the axis that matters.

  • 03

    Our own top-level claims are the ungated artifact

    CLAUDE.md asserts "100% recall / 7.1% false alarms" and "~17%". Neither is derived from anything. The eval floor is 90%/15% — so recall can fall to 90% while the document keeps claiming 100% and CI stays green. For a project whose thesis is "humans read artifacts", that is the defect that matters most.

Ronacher cites none of it.

We extracted every outbound link on his post. The complete external set is two Wikipedia articles, an OpenAI developer blog, one openai/codex permalink, collusion.wiki, and two of his own earlier posts. No arXiv paper. No METR report. No Kilo. No @tenobrus. No system card.

Those sources exist independently and some are strong. But the chain of evidence was assembled by the commentary, not by the engineer whose run is its foundation — which is the citation-laundering pattern this repository already builds gates against.

And his actual claim is far narrower than "GPT-6 writes code humans cannot read". He locates the leakage in two specific places: code one step removed from normal source — "mostly in tests, but also JavaScript or CSS embedded in HTML" — and where nobody is watching, "when it goes all bananza with subagents (where the agent believes nobody is looking)".

The acute loss he describes is not reviewing the final diff. It is following the change while it happens: once the model abandoned the edit tool for Python string splicing, "you're going to have to resort to using the diff viewer of the final artifacts."

That is an observability failure, not a style failure — and observability has a targetable surface.

Corrected 2026-09-16. This bar read +4% through rev 4, and the label said the gain came entirely from non-obvious knowledge. Both were wrong, and wrong in this page's own indicted direction. The +4% is v1's; v2 §4.2 states 2.4%, p = 0.21, and concludes the gain is "neither statistically significant". And the paper runs no decomposition by knowledge type — that is the authors' recommendation quoted as their finding, while their one category-removal ablation found no category significantly affects accuracy.

So the artifact layer pays only when a human puts irrecoverable knowledge into it. An artifact generated from the code is negative-value by measurement. And a stale artifact is not neutral — misleading comments cost 23.2% degradation in output prediction and trigger 2–3× token consumption. Documentation that drifts is active poison, not dead weight.

Two further results close the argument. From OpenAI's own system card:

"Astra often frames the reward-hacking workaround as normal code modularization, while GPT-5.6 Sol more explicitly describes it as bypassing the constraint."

GPT-6 Astra System Card — Impossible Coding Tasks

And prose instruction is weaker than it feels. On the study's primary pool — 1,150 non-baseline runs and 11,637 functions, one codebase, Sonnet 4.6, one trivial // @tracked annotation — an agent followed that instruction only ~64% of the time (the full corpus is 1,650 sessions and 16,050 observations, but about a tenth of those are no-configuration baselines whose rate is 0% by construction, so the grand mean is not this number), with compliance decaying ~5.6% in odds per function generated. File size, instruction position, split-versus-single files, even directly contradicting instructions produced no detectable effect.

Prose to an agent is a suggestion with a two-thirds hit rate that decays as the session runs. An executable gate is a fact.

Defensible version of the premise: humans read artifacts the agent cannot author — test results, behaviour diffs, gate outcomes, production signals — and never the agent's own account of what it did.

One caveat we cannot resolve: there is no published study of a human-facing generated artifact layer as a discipline. It is a reasonable bet, not a finding, and should be labelled that way when we act on it.

§ 03 — The axisWhich rules actually survive

The adversarial pass rejected the framing we started with. "Human-bandwidth artifact versus real rule" does not carve the practices at their joints. The axis that does is checkable / retrieval / perceptual.

gets stronger

Checkable

Types, invariants, tests, contracts, DAG imports, pinned dependencies, idempotency.

The human was the residual enforcer of everything not written down. Remove the human and what is not in a gate is not in the reward. Types are worth ~15% as a defect filter to a person. The +79pp figure this section used to attach to them measures something narrower — compilation success for C under compiler tool access, with functional correctness explicitly disclaimed — so it is evidence for the feedback loop, not for the type system.

survives, machine grounds

Retrieval

Naming, greppability, one-declaration-one-location, module boundaries, section markers.

Context length is a hard machine constraint and identifier text measurably carries semantic signal. The thresholds move; the rule does not. Fixing file-level localisation resolves 14 of 28 file-miss cases and line-level 33 of 175 — but against the 209 unresolved instances those are 6.7% and 15.8%, so in cases actually recovered line-level is worth more than twice as much. Rev 4 quoted the 50%/19% conditional rates as though they ranked the two, which inverts the paper's result.

genuine bandwidth artifact

Perceptual

Line length, punctuation style, blank-line rhythm, formatting.

The only class that was really about a slow reader. Measured as nearly free in both directions — 24.5% token saving for ≤4.2pp accuracy, and no correctness effect across 660 trials. Stop spending rules here.

The 660-trial null is unusually credible: both authors are SonarSource and "cleanliness" is their own product's rule set. They did find effects and led with them — 7-8% fewer tokens, 34% fewer file revisitations, concluding that "traditional maintainability principles remain highly relevant" — which makes the correctness null more striking, not less: it is the one axis their own incentives ran against. Do not quote its token savings per task, though — the median delta is −4.5% and the sign flips on 11 of 27 tasks.

This is where our own proposal died. We drafted a gate on the "machineslop signature" — semicolons and one-line if — then read the eighteen violations in load-bearing configs/. Twelve are deliberate, self-evident idioms: an aligned threshold ladder in claude-usage-watch.py, a cursor-advance in blog_render.py. The other six are not ours to call deliberate — git blame puts all six in vignelli_system.py on one commit, 1ab573b, which absorbed an upstream skill pack from maxsoweski/claude-design-skills. Rev 4 said all eighteen were deliberate without running the blame. The recommendation is still withdrawn — perceptual class, no measured correctness effect — but on twelve examined cases and six inherited ones, not eighteen examined ones.

§ 04 — The trapWhy more gates is not the answer

The strongest attack in the sweep was against the idea we are best at. Gates cannot replace review, and the reason is informational rather than a coverage gap you can close by adding more.

A gate is evidence only if it can be surprised.

A gate tells you about a defect only when passing is less likely given the defect. If the artifact and the gate derive from the same intent-model, an error in that model appears in both — so the probability of passing approaches certainty for exactly the defect class that matters most: we built the wrong thing, correctly.

Gate value is proportional to provenance independence from the generator, not to gate count.

Measured against our own repository: 22 of 22 gates in the syntax-check job are parse, lint, text, or filesystem-consistency checks. Zero check types or behaviour. They caught drift that review missed for 241 commits — and they are blind by construction to wrong requirements, design errors, concurrency, security logic and performance cliffs.

The same trap has a recursive form here. Our meta-gate proves each instrument can still go red — a practice we could not find anywhere else in the literature. But its exemption list, known_gap, contains exactly the four scripts CI runs under the banner "can the harness go red?"

The rules we audited are not in the file we thought.

## Code Architecture (Claude Code-Optimized) lives at configs/CLAUDE.md:196 — the shipped template, byte-identical to the global profile — and not in the project's own CLAUDE.md. Working inside this repository, those seven rules reach a session only through whoever's machine it happens to be. That is a deploy gap, and it is invisible because nothing checks it.

Two of those seven rules do not survive on their own terms. "4–6 modules per component" is in direct arithmetic tension with the 1500-line cap — the cap forces splits, and orchestrator/ holds 61 top-level modules. You cannot hold both: the 492 tracked source files total 138,115 lines. And "shorter files = fewer string duplicates = reliable Edit" was true of a 2025 harness; Edit uniqueness is a property of the string you select, and this harness's Edit carries replace_all.

What we are not doing

  • Not gating formatting or punctuation. Perceptual class. No measured correctness effect in 660 controlled trials, and ruff format --check would reformat 312 of 344 files for the one axis that is nearly free anyway.
  • Not adding a complexity gate yet. The controlled study says cleanliness bought no correctness; the erosion study measures a different thing over a longer horizon. Measure ours first — item 6 — then decide.
  • Not writing more prose rules. ~64% compliance, decaying within a session, with no detectable effect from size or position. We already spend a fifth of CLAUDE.md on the one category measured as not helping.
  • Not piling on structure. Assertion pass rates fell ~30 points as structural requirements accumulated; agents did better in minimal frameworks than convention-heavy ones. "Convention over configuration" is what measurement penalises.
  • Not rewriting our architecture rules from this article. One unattended run, one prompt, an endogenous verifier, n = 1, no control. But equally — we should stop claiming our gates cover code quality, because measurably they do not.

§ 07 — OpenWhat we still do not know

  • Does our own agent-authored code erode the way the literature says? The one measurement that would convert most of this page from inherited evidence into local fact. We have the history.
  • Is the artifact layer a real discipline? No study found, either way. We are betting on it; the bet should be labelled.
  • How much of Ronacher's outcome was harness rather than model? Nobody has run that horizon under a real gate stack. We are one of the few shops equipped to.
